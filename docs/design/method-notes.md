# 方法记录：我们怎么啃下“拍照量纸”

> 这不是功能文档，是**方法记录**：遇到一个“看起来该能算、实际算不出来”的问题时，
> 我们是怎么一步步拆、怎么判断该停、以及跟行家聊完之后哪些改了、哪些没改。
> 写给以后遇到同类问题的人（以及未来的自己）。

## 1. 背景

需求：用户拿一张不干胶纸、拍一张照片，程序自动量出列数、行数、节距。
约束：离线、普通人能用、没有标定设备、精度到 0.3~0.5 mm 就够（打印本身就有 ±0.3 mm 误差）。

结果：**大部分纸能自动量；少数纸要人工点四个角；极少数纸（刻线像白纸）只能靠打印机试打或扫描仪**。
但真正的收获不是“能测多少”，而是把“为什么测不了”说清楚了。

## 2. 工作方法（六条，都有实例）

### 2.1 先量化，再争论

不要用“看着差不多”“应该更准”做判断。同一张图，先用合成数据把误差拆出来：

| 畸变 k1 | 只用纸边 | 标定板校正 |
|---|---|---|
| 0.06 | +0.78 / +0.62 mm | +0.15 / +0.14 mm |
| 0.10 | +1.22 / +1.14 mm | −0.02 / +0.28 mm |

有了这张表，“要不要加标定板”就不再是争论，而是选择。

### 2.2 把“感觉”变成可证伪的小实验

“照片拍不清”不是结论。把它拆成可测的量：边缘对比度几个灰度级？有多少像素宽？
测出来才发现压痕只有 1~2 级（噪声也在同量级），这才解释了为什么 Canny 只出碎片。

### 2.3 先用合成样张验证，再上真实样本

合成数据能精确控制变量（透视角度、畸变系数、噪点），用来判断“算法本身对不对”；
真实样本用来判断“能不能用”。两者不能混。

### 2.4 失败样本要找到“物理原因”

同一批失败，我们最后归成了三类，而不是十几个 bug：

1. **纸边看不见**（白桌面）→ 换深色背景或手动点角；
2. **刻线太淡**（哑光纸只有 1~2 级对比）→ 侧光、背光、换扫描仪；
3. **纸是翘的**（三维形变）→ 压平或用扫描仪。

只有第 1 类能靠算法解决，另外两类是物理问题，**代码背不动**。

### 2.5 失败的记录比成功的记录值钱

试过但没成的方案都留在 `docs/design/photo-measurement.md` 里：格线拉直原型为什么不收敛、
k1+k2 为什么过拟合、扫描线投票为什么票数不够。后来每次想“要不要再试试”，先翻这份记录。

### 2.6 不接受“看起来能行”

凡是置信度 < 0.5 的结果，界面上直接标“仅供参考”；宁可让用户点四个角，也不交一个错数字。

## 3. 与小马（机器视觉工程师）的讨论摘要

对方是机器视觉方向的工程师。下面是讨论里对我们最有用的几条，以及我们实际做了什么。
（私人交流；这里只概括技术观点，不含对方的个人信息。他的 ID 待确认后再补。）

| 他的判断 | 我们的动作 | 结果 |
|---|---|---|
| 单张照片只有 8 自由度（单应），三维形变没有唯一解 | 停止“单张照片恢复三维”这条路 | 认了，不做 |
| 提前标定相机内外参只能治镜头畸变，治不了纸翘 | 保留标定板（治畸变），翘曲改用“压平/扫描仪” | 分工明确 |
| 先确认拿到的到底是不是原图 | 对比 158 KB 聊天图与 5.4 MB 原图 | 分辨率/压缩确实是变量，但**不是**主因 |
| 图像转单通道、小核高斯，别把 1~2 级的边糊掉 | 灰度化 + σ=1.0 模糊 + Sobel | 边缘能出来，但闭合不成轮廓 |
| 沿横竖扫描线找“长间断”，投票定位格线 | 每 3 行一票、按段长过滤后累计 | 票数普遍 < 10，间距乱跳，不可用 |
| JPEG 会毁掉这种软边 | 写进拍摄提示（存原图、别用聊天压缩图） | 已采纳 |
| 看不出东西就别逐像素硬刚，Sobel 出不来就停 | 停掉哑光纸的纯算法路线 | 已采纳 |
| 精度够用就行，不必拟合直线，能定出角点就够 | 改成“四个角 + 单应”，删掉形变场原型 | **最省事的一条**，直接砍掉一堆代码 |

### 我们从这轮讨论里学到的

- 行家先问“你的输入到底是什么”（原图？压缩图？多少像素？），而不是先问算法；
- 他会直接说“这条别做了”——**止损也是专业能力**；
- 我们之前折腾的“格线拉直”正属于他说的“不必拟合”的那类过度设计。

## 4. 结论

1. 精度上限由**纸的平整度和拍摄条件**决定（0.3~0.6 mm），不是算力；
2. 可用的手段只有四种：扫描仪、深色背景自动拍、手动点四角、试打微调；
3. 失败必须给出下一步，不能让用户卡在“量不出来”；
4. 把“做不到”写清楚，比硬做一个不可靠的功能更有价值。
